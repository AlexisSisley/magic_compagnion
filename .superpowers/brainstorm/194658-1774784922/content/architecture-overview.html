Architecture — Life Counter V3

V1 comme base + GameSessionController + nouveaux widgets. Suppression de la V2.

✅ On garde

V1 — life_counter_page.dart
Layout split haut/bas + barre centrale. Refactoré pour utiliser GameSessionController au lieu de SharedPreferences directes
GameSessionController
Logique métier (life, counters, commander damage, elimination, monarch)
Modèles V2
GameSession, PlayerState, LifeEvent, GameFormat, PlayerConfig
GameSessionService
Crash recovery via snapshot SharedPreferences
Widgets V2 réutilisables
CriticalOverlay, EliminationOverlay, DraggablePlayerZone, FormatChip, DiceRollAnimationDialog
PlayerZone V1
Sous-widgets existants (PlayerHeader, LifeDisplay, LifeLog, CounterStrip)

🆕 On ajoute

Grille adaptative (AdaptiveGrid)
Remplace le layout V1 hardcodé par un calcul dynamique topCount/bottomCount basé sur ceil(n/2)
DeathConfirmationOverlay
Timer 2s → overlay "Éliminé ?" avec Non/Oui. Dismissable. Ne bloque jamais les contrôles +/-
DamageHistorySheet (global)
Bottom sheet depuis la barre centrale. Log chronologique filtrable par joueur. Exploite LifeEvent existant
PlayerHistorySheet (personnel)
Tap sur nom du joueur → bottom sheet avec son historique personnel
Mode édition (drag & drop)
Toggle dans la barre centrale. Active DraggablePlayerZone autour de chaque zone. Indicateur visuel "mode édition"

🗑️ On supprime

life_counter_v2_page.dart
Remplacé par la V1 refactorée
LayoutResolver / LayoutType enum
faceToFace/grid/focus → remplacé par AdaptiveGrid
FaceToFaceLayout, GridLayout, FocusLayout
3 widgets layout → remplacés par un seul AdaptiveGrid
QuickStartPage / AdvancedSettingsPage
Le setup se fait via GameSetupModal existant (V1)
PlayerZoneCompact
Plus besoin — tous les joueurs ont la même taille dans la grille
RadialMenu / RadialMenuTrigger
Remplacé par le long press → élimination manuelle + mode édition
